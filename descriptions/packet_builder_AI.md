### Описание изменений и архитектуры модуля:
1. **Назначение модуля**: Объединение метаданных (заголовка), данных амплитудного сканирования (A-scan) и лог-данных в единый упорядоченный пакет для последующей передачи.
2. **Тактовый домен**: Полностью работает на частоте `sys_clk` (80 МГц) в соответствии с правилами проекта. Сброс синхронизирован (`sys_rst_n`).
3. **Структура заголовка**: Заголовок состоит из фиксированного числа 32-битных слов, содержащих сигнатуру (Magic Number), длину пакета, счетчик пакетов и конфигурационные параметры системы (такие как количество накоплений для `ascan` и параметры `vrc`), зафиксированные в момент старта цикла.
4. **Управление потоком**: Используется стандартный интерфейс типа Valid/Ready (`vld`/`rdy`) для бесконфликтного сопряжения с модулем `ascan`, подсистемой логирования и внешним интерфейсом передачи.
5. **Автомат состояний (FSM)**:
   * `IDLE`: Ожидание готовности данных от `ascan` (`i_ascan_ready`) после импульса запуска.
   * `HEADER`: Поочередная выдача слов заголовка.
   * `ASCAN_PAYLOAD`: Трансляция данных из буфера `ascan` во внешний канал.
   * `LOG_PAYLOAD`: Трансляция накопленных лог-данных.

## Модуль `packet_builder`

Модуль предназначен для формирования единого потока данных (пакета) на частоте `sys_clk`. Он собирает метаданные системы, упаковывает их в заголовок фиксированной длины, после чего последовательно прикрепляет к нему данные из модуля `ascan` и данные логов из модуля `log`.

### Структура пакета данных (32-битные слова)

| Номер слова | Поле | Описание |
| :--- | :--- | :--- |
| **Слово 0** | `MAGIC_NUMBER` | Сигнатура начала пакета (`0x5A5A5A5A`) |
| **Слово 1** | `TOTAL_LENGTH` | Полный размер пакета в 32-битных словах (Заголовок + A-scan + Log) |
| **Слово 2** | `PACKET_ID` | Инкрементный счетчик пакетов (индекс запуска по `i_sync`) |
| **Слово 3** | `ASCAN_LENGTH` | Размер полезной нагрузки A-scan в словах (параметр накопления N) |
| **Слово 4** | `LOG_LENGTH` | Размер полезной нагрузки Log в словах |
| **Слово 5** | `PARAM_ASCAN_ACC`| Зафиксированное значение количества накоплений (из `adc_latch_param`) |
| **Слово 6** | `RESERVED_0` | Зарезервировано для параметров VRC / настроек зондирующего импульса |
| **Слово 7** | `RESERVED_1` | Зарезервировано под контрольную сумму (CRC) или статус устройства |
| **Слово 8..M**| `ASCAN_DATA` | Данные из буфера «бабочки» модуля `ascan` (32-битные упакованные слова) |
| **Слово M+1..N**| `LOG_DATA` | Данные логов от модуля `log` |

### Порты модуля `packet_builder`

```verilog
module packet_builder (
    // Тактирование и сброс (домен sys_clk)
    input  wire        sys_clk,          // Частота 80MHz
    input  wire        sys_rst_n,        // Синхронизированный сброс (активный низкий)

    // Синхронизация запуска цикла
    input  wire        i_sys_sync,       // Импульс начала цикла от sync_cc

    // Системные параметры для записи в заголовок (из модуля param/latch в домене sys_clk)
    input  wire [15:0] i_ascan_acc_num,  // Количество накапливаемых слов для ascan
    input  wire [31:0] i_vrc_param_info, // Текущие параметры VRC или другие метаданные

    // Интерфейс данных от модуля ascan (частота sys_clk)
    input  wire        i_ascan_ready,    // Сигнал готовности данных от ascan (o_data_ready)
    input  wire [31:0] i_ascan_data,     // Упакованные 32-битные данные (o_out_data)
    input  wire        i_ascan_vld,      // Валидность данных ascan (o_out_vld)
    output wire        o_ascan_rdy,      // Готовность принять данные (i_out_rdy для ascan)

    // Интерфейс данных от модуля log (частота sys_clk)
    input  wire        i_log_ready,      // Готовность лог-данных к чтению
    input  wire [31:0] i_log_data,       // Данные логов
    input  wire        i_log_vld,        // Валидность данных логов
    output wire        o_log_rdy,        // Готовность принять данные от log

    // Выходной стриминговый интерфейс пакета (на частоте sys_clk во внешний приёмник)
    output wire [31:0] o_packet_data,    // Выходные данные пакета (Заголовок -> A-scan -> Log)
    output wire        o_packet_vld,     // Валидность выходных данных
    input  wire        i_packet_rdy      // Готовность приемника пакета принимать данные
);
```

### Логика работы автомата состояний (FSM)

Модуль управляется конечным автоматом со следующими состояниями:

1. **`ST_IDLE` (Ожидание)**:
   * Автомат ожидает прихода импульса готовности от модуля ascan (`i_ascan_ready`).
   * При переходе в работу фиксируются текущие значения параметров (`i_ascan_acc_num`, `i_vrc_param_info`) во внутренние регистры, чтобы избежать их изменения в процессе передачи текущего пакета. Инкрементируется внутренний счетчик пакетов `PACKET_ID`.

2. **`ST_HEADER` (Передача заголовка)**:
   * Модуль последовательно выдает 8 слов заголовка на выход `o_packet_data`.
   * Каждое слово передается с подтверждением по интерфейсу `o_packet_vld` и `i_packet_rdy`. После передачи последнего слова заголовка автомат переходит к передаче полезной нагрузки.

3. **`ST_ASCAN_PAYLOAD` (Передача данных A-scan)**:
   * Выходной интерфейс напрямую коммутируется с интерфейсом модуля `ascan`:
     * `o_packet_data` = `i_ascan_data`
     * `o_packet_vld` = `i_ascan_vld`
     * `o_ascan_rdy` = `i_packet_rdy`
   * Состояние удерживается до тех пор, пока не будет передано ровно `i_ascan_acc_num` (или вычисленное на его основе число слов) данных.

4. **`ST_LOG_PAYLOAD` (Передача данных LOG)**:
   * Выходной интерфейс коммутируется с интерфейсом модуля `log`:
     * `o_packet_data` = `i_log_data`
     * `o_packet_vld` = `i_log_vld`
     * `o_log_rdy` = `i_packet_rdy`
   * Передается фиксированное или динамическое количество лог-слов. После завершения передачи автомат возвращается в состояние `ST_IDLE`.
