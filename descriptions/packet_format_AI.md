Вот подробное техническое описание формата данных пакета, формируемого модулем `packet_builder.v` на частоте `sys_clk` (80 МГц).

# Описание формата выходного пакета (packet_builder)

Модуль `packet_builder` собирает воедино системные параметры (заголовок), данные А-скана (A-scan payload) и данные логарифмического канала (Log payload) в единый непрерывный поток 32-битных слов. 

Передача пакета осуществляется по интерфейсу, совместимому с протоколом типа **Avalon-ST / AXI-Stream** (сигналы `o_packet_data`, `o_packet_vld`, `i_packet_rdy`).

---

## 1. Общая структура пакета

Пакет состоит из трех последовательных частей. Общий размер пакета динамический и зависит от настроек количества точек А-скана и логарифмического канала.

| Секция пакета | Размер (32-битных слов) | Описание |
| :--- | :--- | :--- |
| **Заголовок (Header)** | 14 слов (фиксировано) | Метаданные, ID пакета и копия всех конфигурационных параметров на момент старта. |
| **A-scan Payload** | `N_ascan` слов (динамический) | Данные А-скана от модуля `ascan` (длина задается параметром `r_ascan_n_samples`). |
| **Log Payload** | `N_log` слов (динамический) | Данные логарифма от модуля `log` (длина задается параметром `r_log_n_samples`). |

**Полный размер пакета** = $14 + N_{ascan} + N_{log}$ (32-битных слов).

*Примечание: Если один из параметров количества точек ($N_{ascan}$ или $N_{log}$) равен 0, соответствующая секция полезной нагрузки полностью пропускается в потоке данных.*

---

## 2. Детальная структура заголовка (Header)

Заголовок состоит строго из **14 слов** (Word 0 .. Word 13) разрядностью 32 бита.

| :---: | :---: | :--- | :--- |
| **0** | `[31:0]` | **MAGIC_NUMBER** | Константа синхронизации кадра: `32'h5A5A5A5A` |
| **1** | `[31:0]` | **TOTAL_LENGTH** | Полная длина пакета в 32-битных словах ($14 + N_{ascan} + N_{log}$) |
| **2** | `[31:0]` | **PACKET_ID** | Сквозной инкрементирующийся счетчик пакетов (увеличивается по `i_sys_sync`) |
| **3** | `[31:16]` | *Резерв* | Заполнено нулями (`16'd0`) |
| | `[15:0]` | **ASCAN_LENGTH** | Кол-во слов в полезной нагрузке А-скана ($N_{ascan}$) |
| **4** | `[31:16]` | *Резерв* | Заполнено нулями (`16'd0`) |
| | `[15:0]` | **LOG_LENGTH** | Кол-во слов в полезной нагрузке логарифма ($N_{log}$) |
| **5** | `[31:16]` | **ASCAN_DELAY** | Задержка старта А-скана (`r_ascan_delay_time`) |
| | `[15:8]` | **ASCAN_ACCUM** | Количество накоплений А-скана (`r_ascan_accum`) |
| | `[7:4]` | **ASCAN_ACC_TYPE**| Тип накопления А-скана (`r_ascan_accum_type`) |
| | `[3:0]` | *Резерв* | Заполнено нулями (`4'd0`) |
| **6** | `[31:16]` | **LOG_SKIP_TICKS**| Пропуск тактов логарифма (`r_log_skip_ticks`) |
| | `[15:8]` | **LOG_ACCUM** | Количество накоплений логарифма (`r_log_accum`) |
| | `[7:4]` | **LOG_ACC_TYPE** | Тип накопления логарифма (`r_log_accum_type`) |
| | `[3:0]` | **LOG_TRANS_METH**| Метод преобразования логарифма (`r_log_trans_meth`) |
| **7** | `[31:16]` | **PULSE_CHARGE** | Время заряда ключа ВВ импульса (`r_pulse_charge_time`) |

| **8** | `[31:24]` | **PULSE_WIDTH** | Ширина импульса возбуждения (`r_pulse_width`) |
| | `[23:16]` | **VRC_DAC_DIV** | Делитель частоты DAC ВАРУ (`r_vrc_dac_div`) |
| | `[15:14]` | **VRC_TYPE** | Тип регулировки ВАРУ (`r_vrc_type`) |
| | `[13:0]` | *Резерв* | Заполнено нулями |
| **9** | `[31:16]` | **VRC_START_DELAY**| Задержка начала работы ВАРУ (`r_vrc_start_delay`) |
| | `[15:11]` | *Резерв* | Заполнено нулями (`5'd0`) |
| | `[10:0]` | **VRC_INIT_GAIN** | Начальное усиление ВАРУ (`r_vrc_init_gain`) |
| **10** | `[31:26]` | *Резерв* | Заполнено нулями |
| | `[25:16]` | **VRC_DAC_MAX** | Максимальный предел ЦАП ВАРУ (`r_vrc_dac_max`) |
| | `[15:10]` | *Резерв* | Заполнено нулями |
| | `[9:0]` | **VRC_DAC_MIN** | Минимальный предел ЦАП ВАРУ (`r_vrc_dac_min`) |
| **11** | `[31:0]` | **VRC_RATE_1** | Скорость нарастания 1 ВАРУ (`r_vrc_rate_1`, float * $2^P$) |
| **12** | `[31:0]` | **VRC_RATE_2** | Скорость нарастания 2 ВАРУ (`r_vrc_rate_2`, float * $2^P$) |
| **13** | `[31:16]` | **VRC_DUR_1** | Время нарастания 1 ВАРУ (`r_vrc_duration_1`) |
| | `[15:0]` | **VRC_DUR_2** | Время нарастания 2 ВАРУ (`r_vrc_duration_2`) |

## 3. Полезная нагрузка (Payload)

### 3.1. Данные А-скана (A-scan Payload)
Идет сразу после Word 13 заголовка, если `ASCAN_LENGTH` > 0.
Представляет собой последовательность из `ASCAN_LENGTH` слов по 32 бита.
Данные поступают напрямую из буфера памяти «бабочка» модуля `ascan` на частоте `sys_clk`. Внутри этих 32-битных слов упакованы исходные 12-битные отсчеты АЦП (упаковка производится в модуле `ascan`).

### 3.2. Данные логарифмического канала (Log Payload)
Идет сразу после окончания данных А-скана (или сразу после заголовка, если `ASCAN_LENGTH` был равен 0), при условии, что `LOG_LENGTH` > 0.
Представляет собой последовательность из `LOG_LENGTH` слов по 32 бита.
Данные поступают из модуля обработки логарифмического канала `log`.

---

## 4. Логика управления и квитирования потока

Передача осуществляется по классической схеме Ready/Valid-рукопожатия (Handshake):
1. Данные в шине `o_packet_data` считаются действительными в текущем такте `sys_clk`, только если `o_packet_vld == 1`.
2. Продвижение потока (инкремент адреса чтения/счетчиков слов) происходит только тогда, когда в одном такте выполняются условия: 
   $$\text{o\_packet\_vld} \ \ \&\& \ \ \text{i\_packet\_rdy} == 1$$
3. Если внешний приемник сбрасывает `i_packet_rdy` в `0`, передатчик замораживает текущее слово на выходе и ждет готовности приемника.
4. В момент перехода из состояния `ST_IDLE` в `ST_HEADER` по сигналу готовности данных А-скана (`i_ascan_ready`) происходит мгновенное защелкивание (latch) всех конфигурационных параметров во внутренние регистры `r_*`. Это гарантирует, что даже если в процессе передачи пакета управляющий компьютер изменит регистры параметров, внутри текущего кадра все метаданные в заголовке будут строго соответствовать реальным физическим параметрам, при которых был собран данный кадр.
