### Подробное понимание работы модуля `log`

Модуль предназначен для сбора, предварительной обработки (децимирования, фильтрации, масштабирования), буферизации и передачи данных, поступающих от АЦП логарифмического усилителя (AD8310ARZ). Он решает классическую задачу согласования частот (Clock Domain Crossing, CDC) между быстрой шиной обработки (`sys_clk`) и частотой оцифровки (`log_clk`).

#### 1. Тактовые домены и синхронизация (CDC)
Модуль разделен на два независимых частотных домена, взаимодействие между которыми происходит через двухпортовую память (Dual-Port RAM):
*   **Домен `log_clk` (25 МГц):**
    *   Здесь происходит захват сырых данных с АЦП (`i_adc_data` [9:0]).
    *   Выполняется децимирование (прореживание) и преобразование разрядности (10 бит -> 8 бит).
    *   Упакованные данные записываются в активную половину двухпортовой памяти.
    *   Все управляющие параметры (`i_n_samples` [15:0], `i_accum` [7:0], `i_accum_type` [3:0], `i_trans_meth` [3:0], `i_skip_ticks` [15:0]) и сигнал запуска (`i_log_sync`) действуют в этом домене.
*   **Домен `sys_clk` (80 МГц):**
    *   В этом домене работает интерфейс выдачи готовых данных во внешнюю систему.
    *   Чтение происходит по классическому протоколу типа AXI-Stream: потребитель сообщает о готовности через `i_out_rdy`, модуль выставляет данные на `o_out_data` и валидирует их сигналом `o_out_vld`.
    *   Здесь же формируются сигналы готовности пакета (`o_data_ready`) и его размер (`o_out_size`).

#### 2. Конвейер обработки данных (в домене `log_clk`)
После прихода импульса запуска `i_log_sync` модуль начинает обрабатывать поток `i_adc_data` по следующему алгоритму:

1.  **Задержка начала обработки (Skip Delay):**
    После фиксации стартового импульса `i_log_sync` модуль выдерживает паузу в `i_skip_ticks` [15:0] тактов частоты `log_clk`. В течение этого времени поступающие отсчеты АЦП аппаратно игнорируются и в буфер не записываются. Это позволяет пропускать нежелательные переходные процессы или аппаратно сдвигать «окно» измерения относительно момента запуска.

2.  **Прореживание (Decimation / Accumulation):**
    Выполняется во внутреннем модуле `log_decimator`.
    По окончании задержки модуль группирует входящие отсчеты пачками по `i_accum` [7:0] штук. Из каждой пачки формируется один отсчет в зависимости от настройки `i_accum_type` [3:0]:
    *   `i_accum_type == 1` (Пиковый детектор): на выход идет максимальное значение из `i_accum` тактов.
    *   `i_accum_type == 2` (Интегратор/Среднее значение): вычисляется среднее арифметическое (сумма деленная на `i_accum`).

3.  **Сжатие разрядности (Compression 10-bit -> 8-bit):**
    Выполняется во внутреннем модуле `log_compressor`.
    Полученный после децимирования отсчет приводится к 8-битному формату согласно параметру `i_trans_meth` [3:0]:
    *   `i_trans_meth == 1` (Сдвиг): производится отбрасывание младших бит (например, логический сдвиг вправо на 2 бита `>> 2`), чтобы уместить данные в диапазон `0..255`.
    *   `i_trans_meth == 2` (Насыщение / Клиппинг): если значение превышает `255`, оно жестко ограничивается величиной `255` (насыщение), иначе берется как есть (или с другой логикой приведения, если разрядность исходного сигнала выше 8 бит).
    *   `i_trans_meth == 3` (Сдвиг на 1 и насыщение): значение предварительно сдвигается вправо на 1 бит (`>> 1`), после чего полученный результат проверяется на превышение порога `255`. Если значение больше `255`, оно жестко ограничивается (насыщается) до величины `255`, иначе берется как есть.

4.  **Упаковка (Packing):**
    Выполняется во внутреннем модуле `log_packer`.
    Поскольку память имеет 32-битную организацию, каждые 4 обработанных 8-битных отсчета упаковываются в одно 32-битное слово.

5.  **Запись в буфер памяти:**
    Упакованное 32-битное слово записывается в текущий активный буфер DPRAM. Процесс идет до тех пор, пока количество обработанных исходных отсчетов АЦП не достигнет заданного в параметре `i_n_samples` (или пока не заполнится заданное количество упакованных слов, эквивалентное `i_n_samples`).

#### 3. Архитектура буферизации (Двойной буфер / "Бабочка" / Ping-Pong)
Для непрерывной работы без потери данных в модуле реализован двойной буфер (Ping-Pong RAM):
*   **Буфер А** и **Буфер Б**.
*   В то время как в **Буфер А** идет запись новых данных на частоте `log_clk`, из **Буфера Б** внешняя система может одновременно вычитывать ранее накопленные данные на частоте `sys_clk`.
*   Как только в записываемом буфере накапливается объем, соответствующий параметрам, происходит переключение (смена ролей буферов):
    *   Запись перенаправляется в освободившийся буфер.
    *   Для заполненного буфера в домен `sys_clk` передается сигнал готовности `o_data_ready` и количество доступных для чтения 32-битных слов в `o_out_size`.
    *   Передача сигналов состояния между доменами (`log_clk` -> `sys_clk`) требует аккуратной синхронизации (например, через классическое квитирование или передачу указателей в коде Грея).

#### 4. Внутренняя структура и декомпозиция (Иерархия модулей)
Для повышения модульности и удобства отладки вся логика математической обработки данных вынесена в отдельные вспомогательные модули, расположенные **внутри одного физического файла** `log.v` (или `log.sv`):

##### 4.1. Модуль децимирования (`log_decimator`)
Отвечает за прореживание данных по алгоритму пикового детектора или интегратора.
*   **Входы:**
    *   `log_clk` — тактовая частота 25 МГц.
    *   `log_rst_n` — сброс домена.
    *   `i_data [9:0]` — сырые данные АЦП.
    *   `i_vld` — валидность входных данных (активен после окончания Skip Delay).
    *   `i_accum [7:0]` — размер окна децимирования.
    *   `i_accum_type [3:0]` — тип обработки (1 — пик, 2 — среднее).
*   **Выходы:**
    *   `o_data [9:0]` — результат децимирования (10-битное значение после нахождения пика или деления суммы на `i_accum`). Внутренний регистр накопления суммы может иметь разрядность до 18 бит (`[17:0]`) для предотвращения переполнения в процессе расчета.
    *   `o_vld` — строб готовности отсчета (выставляется один раз на каждые `i_accum` входных тактов).

##### 4.2. Модуль компрессии (`log_compressor`)
Отвечает за приведение разрядности из 10-битного формата децимированных данных к 8-битному.
*   **Входы:**
    *   `log_clk`, `log_rst_n`.
    *   `i_data [9:0]` — данные после децимирования.
    *   `i_vld` — строб готовности входных данных.
    *   `i_trans_meth [3:0]` — метод компрессии (1 — сдвиг, 2 — насыщение, 3 — сдвиг на 1 и насыщение).
*   **Выходы:**
    *   `o_data [7:0]` — сжатые 8-битные данные.
    *   `o_vld` — строб валидности выходных данных.

##### 4.3. Модуль упаковки (`log_packer`)
Накапливает 8-битные отсчеты и формирует 32-битные слова для записи в DPRAM.
*   **Входы:**
    *   `log_clk`, `log_rst_n`.
    *   `i_data [7:0]` — сжатые данные.
    *   `i_vld` — строб валидности данных.
    *   `i_sync` — импульс начала пакета (для сброса внутренних указателей упаковщика в исходное состояние).
*   **Выходы:**
    *   `o_word [31:0]` — упакованное 32-битное слово.
    *   `o_write` — строб записи в память (активен один раз на каждые 4 входных байта).
