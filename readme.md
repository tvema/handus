
## Технический анализ и систематизация правил (Понимание ИИ)

### 1. Свод правил именования сигналов (Naming Convention)
* **Входные сигналы:** Всегда имеют префикс `i_` (например, `i_in_data`, `i_out_rdy`).
* **Выходные сигналы:** Всегда имеют префикс `o_` (например, `o_out_data`, `o_out_vld`, `o_data_ready`).
* **Тактовые сигналы (Исключение):** Строго `<domain>_clk` без префикса `i_` (например, `sys_clk`, `adc_clk`).
* **Сигналы сброса (Исключение):** Строго `<domain>_rst_n` (асинхронный, активный низкий), без префикса `i_` (например, `sys_rst_n`, `adc_rst_n`).
* **Входной сигнал запуска/синхронизации:** Строго `i_<domain>_sync` (например, `i_adc_sync`, `i_sys_sync`).

### 2. Сетка частотных доменов (Clock Domains)
* **`sys_clk` (80 MHz):** Системный домен. Обработка команд, чтение накопленных данных, системная логика.
* **`adc_clk` (65 MHz):** Домен АЦП. Скоростной захват данных, защёлкивание параметров захвата.
* **`log_clk` (25 MHz):** Логический домен.
* **`dac_clk` (30 MHz):** Домен ЦАП.
* **`hi_clk` (250 MHz):** Высокочастотный импульсный домен для модуля `hi_pulse`.

### 3. Междоменная синхронизация (Clock Domain Crossing - CDC)
* **`sync_cc` (Ядро CDC):** Централизованный модуль для безопасной передачи асинхронных сигналов. 
  * Он принимает одиночный импульс `i_sync` на частоте `sys_clk` и транслирует его во все домены как синхронные стробы `o_*_sync`.
  * Он принимает общий асинхронный сброс `rst_n` и выдает сбросы `o_*_rst_n`, синхронизированные с фронтами соответствующих тактовых сигналов (генерация синхронного снятия сброса).
* **Передача данных (Ping-Pong RAM):** Междоменная передача данных из `adc_clk` (65 MHz) в `sys_clk` (80 MHz) в модуле `ascan` решена через двухпортовую память по схеме «бабочка» (двойной буфер). Пока один буфер пишется на `adc_clk`, второй читается на `sys_clk`.

### 4. Алгоритмы и логика работы модулей

#### А. Декодер команд и параметров (`param`, домен `sys_clk`)
* Принимает команды в виде двух 32-битных шин (Адрес и Данные) с сигналом валидности (`i_cmd_vld`).
* Маршрутизация на основе старшего байта адреса (`addr[31:24]`):
  * `1` $\rightarrow$ Текущий домен `sys_clk`.
  * `2` $\rightarrow$ Домен `adc_clk` (команда уходит транзитом в `adc_latch_param`).
  * `3` $\rightarrow$ Домен `log_clk`.
  * `4` $\rightarrow$ Домен `dac_clk`.
  * `5` $\rightarrow$ Домен `hi_clk`.
* Система гарантирует, что все модули-приемники всегда готовы принять команду.

#### Б. Локальные параметры АЦП (`adc_latch_param`, домен `adc_clk`)
* Получает транзитные команды из `param`, декодирует их на частоте `adc_clk`.
* **Важное правило обновления параметров:** Значения команд не применяются мгновенно, а защёлкиваются в рабочие регистры строго по импульсу `i_adc_sync`. Это гарантирует стабильность параметров на протяжении всего цикла работы.
* **Специальный параметр:** При адресе `i_cmd_addr[23:16] == 8'h01` младшие 16 бит данных `i_cmd_data[15:0]` определяют параметр $N$ (количество накапливаемых 32-битных слов для `ascan`).

#### В. Модуль накопления `ascan` (Двухпортовый CDC-буфер, `adc_clk` / `sys_clk`)
* **Фаза записи (`adc_clk`):**
  * Поток 12-битных данных `i_in_data` поступает каждый такт `adc_clk`.
  * Приход импульса `i_adc_sync` активирует процесс записи.
  * Выполняется упаковка: каждые три отсчета по 12 бит или последовательная упаковка в 32-битное слово.
  * Запись идет в активный буфер Ping-Pong памяти.
  * Если объявлен макрос `TESTMODE`, используется поведенческая (программная) модель памяти, иначе синтезируется аппаратная `altsyncram` (Quartus IP).
* **Переключение буферов и Фаза чтения (`sys_clk`):**
  * После записи $N$ слов в текущий буфер, процесс записи переключается на второй буфер.
  * Для домена `sys_clk` выставляется флаг `o_data_ready`.
  * Данные вычитываются по шине `o_out_data` [31:0] с использованием протокола квитирования: валидация `o_out_vld` и готовность приемника `i_out_rdy`.
