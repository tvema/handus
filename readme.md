# Проект FPGA: Система сбора данных и управления ВАРУ / УЗ-зондированием

Настоящий документ содержит спецификацию архитектуры, правила междоменной синхронизации (CDC), соглашение об именовании сигналов, сводную регистровую карту параметров и детальное описание логики работы аппаратных модулей системы.

---

## 1. Сетка частотных доменов (Clock Domains)

Все тактовые частоты генерируются специализированным блоком PLL. Параметры частот и их фазовые соотношения зафиксированы во внешнем `.sdc` (Synopsys Design Constraints) файле автомата временного анализа.

| Имя тактовой частоты | Частота | Описание домена |
| :--- | :--- | :--- |
| sys_clk | 80 MHz | Системный домен. Команды управления, интерфейсы чтения данных |
| adc_clk | 65 MHz | Домен АЦП. Скоростной захват сигналов, накопление данных |
| log_clk | 25 MHz | Домен вспомогательной системной логики |
| dac_clk | 50 MHz | Домен ЦАП. Генерация напряжений ВАРУ (управление трактом AD604) |
| hi_clk | 250 MHz | Высокочастотный домен для субтактового управления импульсом |

## 2. Свод правил именования сигналов (Naming Convention)

Для обеспечения читаемости кода и корректной автоматической верификации CDC-путей в проекте строго соблюдаются следующие правила именования:

1. **Входные порты модулей:** Начинаются строго с префикса `i_` (например, `i_in_data`, `i_out_rdy`).
2. **Выходные порты модулей:** Начинаются строго с префикса `o_` (например, `o_out_data`, `o_data_ready`).
3. **Тактовые сигналы:** Называются строго без префикса `i_`: `<domain>_clk` (например, `sys_clk`, `adc_clk`, `log_clk`, `dac_clk`, `hi_clk`).
4. **Сбросы (Resets):** Называются строго без префикса `i_`, имеют суффикс `_rst_n` (активный низкий уровень): `<domain>_rst_n` (например, `sys_rst_n`, `adc_rst_n`).
5. **Сигналы синхронизации (Sync):** Входной запускающий импульс в конкретном домене именуется как `i_<domain>_sync`.

## 3. Модуль глобальной синхронизации `sync_cc`

Модуль `sync_cc` является центральной точкой распределения синхроимпульсов запуска и дерева сброса проекта. Он реализует:
1. Кросс-клокинг (CDC) единого сигнала запуска `i_sync` (приходящего на частоте `sys_clk`) во все остальные частотные домены в виде одиночных стробов (`o_*_sync`).
2. Буферизацию и безопасную деассерцию асинхронного системного сброса `rst_n` индивидуально для каждого домена (`o_*_rst_n`), предотвращая метастабильность триггеров сброса.

### Заголовок модуля sync_cc:
```verilog
module sync_cc (
    // Входной тактовый сигнал домена sys_clk (80MHz) и глобальный сброс
    input  wire clk,         // sys_clk (80MHz) согласно правилу наименования
    input  wire rst_n,       // Асинхронный сброс (активный низкий)

    // Входной сигнал синхронизации в домене sys_clk
    input  wire i_sync,      // Сигнал внешней синхронизации

    // Тактовые частоты других доменов
    input  wire i_adc_clk,   // adc_clk: 65MHz
    input  wire i_log_clk,   // log_clk: 25MHz
    input  wire i_dac_clk,   // dac_clk: 50MHz
    input  wire i_hi_clk,    // hi_clk:  250MHz

    // Выходные синхронизированные импульсы для каждого домена
    output wire o_sys_sync,  // Синхронизирован в sys_clk (80MHz)
    output wire o_adc_sync,  // Синхронизирован в adc_clk (65MHz)
    output wire o_log_sync,  // Синхронизирован в log_clk (25MHz)
    output wire o_dac_sync,  // Синхронизирован в dac_clk (50MHz)
    output wire o_hi_sync,   // Синхронизирован в hi_clk  (250MHz)

    // Выходные синхронизированные сбросы (активный низкий) для каждого домена
    output wire o_sys_rst_n, // Сброс для домена sys_clk (80MHz)
    output wire o_adc_rst_n, // Сброс для домена adc_clk (65MHz)
    output wire o_log_rst_n, // Сброс для домена log_clk (25MHz)
    output wire o_dac_rst_n, // Сброс для домена dac_clk (50MHz)
    output wire o_hi_rst_n   // Сброс для домена hi_clk  (250MHz)
);
```

## 4. Спецификация модулей системы

### 4.1. Модуль декодирования параметров `param` (домен `sys_clk`)
Служит для глобального приема и маршрутизации конфигурационных параметров.
* **Входные данные:** Два 32-битных слова: адрес команды (`i_cmd_addr`) и данные команды (`i_cmd_data`). Сопровождаются сигналом валидности `i_cmd_vld`.
* **Маршрутизация команд:** Осуществляется по старшему байту адреса команды (`i_cmd_addr[31:24]`):
  * `8'h01` -> Текущий домен `sys_clk`.
  * `8'h02` -> Домен `adc_clk` (команда передается транзитом в `adc_latch_param`).
  * `8'h03` -> Домен `log_clk` (команды настройки параметров логарифмического накопителя).
  * `8'h04` -> Домен `dac_clk` (команды для ВАРУ).
  * `8'h05` -> Домен `hi_clk` (параметры длительности импульсов зондирования).
* **Свойство интерфейса:** Считается, что все принимающие модули всегда готовы к обработке поступающих команд (`ready` всегда активен). Передача выполняется по факту наличия флага валидности `i_cmd_vld`.

### 4.2. Модуль локальных параметров `adc_latch_param` (домен `adc_clk`)
Принимает транзитные команды из модуля `param`, декодирует их и осуществляет защёлкивание в локальные регистры конфигурации.
* **Механика обновления:** Чтобы исключить искажение параметров "на лету" во время активного цикла измерения, новые значения защёлкиваются из теневых регистров в рабочие только по фронту синхроимпульса запуска `i_adc_sync`.
* **Параметр накопления:** При адресе команды `i_cmd_addr[23:16] == 8'h01` младшие 16 бит данных `i_cmd_data[15:0]` определяют параметр $N$ — количество накапливаемых 32-битных слов для работы модуля `ascan`.

### 4.3. Высоковольтный импульсный генератор `pulse` (домен `hi_clk` - 250 MHz)
Управляет внешними ключами накачки и формирования высоковольтного импульса зондирования. Модуль функционирует на базе конечного автомата (FSM), тактируемого высокой частотой 250 MHz для достижения высокой точности временных интервалов.

#### Алгоритм переходов FSM и состояния выходов:
1. **`NONE` (Исходное состояние):** Ожидание пускового импульса синхронизации `i_hi_sync`. 
   * *Выходы:* `power_on = 0` (выключено), `strike = 0` (выключено).
2. **`CHARGE` (Зарядка силового накопительного контура):** Переход по событию `i_hi_sync`. Состояние удерживается ровно `i_charge_time` тактов.
   * *Выходы:* `power_on = 1` (включено), `strike = 1` (включено).
3. **`TRANSMIT` (Передача мощности в тракт):** Переход по окончании зарядки. Состояние удерживается ровно `i_transmit_time` тактов.
   * *Выходы:* `power_on = 1` (включено), `strike = 0` (выключено).
4. **`STRIKE` (Выстрел / Формирование фронта импульса):** Состояние удерживается ровно `i_pulse_width` тактов.
   * *Выходы:* `power_on = 1` (включено), `strike = 0` (выключено).
5. **`POWER_OFF` (Пауза деактивации):** Принудительное безопасное состояние отключения силовых цепей. Удерживается не менее **200 тактов**. Предотвращает тепловую перегрузку и пробой силовых ключей. По окончании выдержки времени FSM возвращается в состояние ожидания `NONE`.
   * *Выходы:* `power_on = 0` (выключено), `strike = 0` (выключено).

```
               ┌───────────────────────┐
               │         NONE          │◄──────────────────────┐
               └───────────┬───────────┘                       │
                           │ i_hi_sync                         │
                           ▼                                   │
               ┌───────────────────────┐                       │
               │        CHARGE         │                       │
               │(i_charge_time тактов) │                       │
               └───────────┬───────────┘                       │
                           │                                   │
                           ▼                                   │
               ┌───────────────────────┐                       │
               │       TRANSMIT        │                       │
               │(i_transmit_time тактов)                       │
               └───────────┬───────────┘                       │
                           │                                   │
                           ▼                                   │
               ┌───────────────────────┐                       │
               │        STRIKE         │                       │
               │ (i_pulse_width тактов)│                       │
               └───────────┬───────────┘                       │
                           │                                   │
                           ▼                                   │
               ┌───────────────────────┐                       │
               │       POWER_OFF       │                       │
               │  (>= 200 тактов)      ├───────────────────────┘
               └───────────────────────┘
```

### 4.4. Модуль накопления данных `ascan` (домены `adc_clk` / `sys_clk`)
Модуль обеспечивает захват высокоскоростных 12-битных отсчетов АЦП, их упаковку и безопасную передачу в медленный системный домен без пропусков данных.

* **Входные данные:** Поток 12-битных данных `i_in_data` на частоте `adc_clk` (новые данные поступают на каждом такте).
* **Запись и накопление (`adc_clk`):** 
  * Процесс захвата инициируется по фронту строба `i_adc_sync`.
  * Поступающие 12-битные данные упаковываются в 32-битные слова.
  * Память модуля организована по схеме двухбуферной структуры «бабочка» (double-buffering / Ping-Pong): пока один буфер заполняется на частоте `adc_clk`, из второго буфера накопленные ранее данные параллельно считываются в домене `sys_clk`.
  * **Условная компиляция памяти:** Если в проекте определен глобальный макрос `` `define TESTMODE `₁, то в качестве ОЗУ компилируется поведенческая модель-заглушка. В противном случае синтезируется аппаратный IP-блок Quartus `altsyncram`.
* **Чтение и передача (`sys_clk`):**
  * Как только буфер накапливает требуемые $N$ слов, на частоте `sys_clk` выставляется флаг готовности данных `o_data_ready`.
  * Выдача данных на шину `o_out_data [31:0]` производится с использованием классического протокола квитирования: данные сопровождаются сигналом валидности `o_out_vld` и передаются только при наличии сигнала готовности приемника `i_out_rdy` (Handshake).

```
       [ i_in_data (12-бит) @ adc_clk ]
                     │
                     ▼
          [ Упаковка в 32 бита ]
                     │
             ┌───────┴───────┐
             ▼               ▼
        ┌─────────┐     ┌─────────┐
        │ Буфер А │     │ Буфер Б │  (Двухпортовая RAM "Бабочка")
        └─────────┘     └─────────┘
             │               │
             └───────┬───────┘
                     ▼
       [ o_out_data (32-бит) @ sys_clk ] (Квитирование vld / rdy)
```

### 4.5. Драйвер ЦАП `dac_spi` (домен `dac_clk` - 50 MHz)
Интерфейсный модуль физического уровня для работы с внешней микросхемой ЦАП DAC101S101.
* Обеспечивает последовательную выдачу данных по SPI-совместимому протоколу (формирование линий SYNC, SCLK, DIN).
* Принимает очередное 10-битное значение от генератора профиля ВАРУ `vrc`, подтверждая прием с помощью сигналов квитирования (валидность/готовность).

### 4.6. Генератор профиля ВАРУ `vrc` (домен `dac_clk` - 50 MHz)
Реализует функцию временной регулировки усиления (ВАРУ / Time-Gain Control) для двух последовательно включенных малошумящих усилителей AD604 с аналоговым управлением.

* **Входные параметры профиля:**
  * `vrc_type [1:0]` — режим работы/тип совместной регулировки каналов.
  * `delay_start [15:0]` — время задержки начала регулирования (в тактах `dac_clk`).
  * `init_gain [10:0]` — начальное значение усиления.
  * `slope_1 [31:0]` — скорость нарастания на первом участке.
  * `time_1 [15:0]` — длительность первого участка нарастания (в тактах).
  * `slope_2 [31:0]` — скорость нарастания на втором участке.
  * `time_2 [15:0]` — длительность второго участка нарастания (в тактах).
  * `min_dac [9:0]` — минимально допустимый код для ЦАП.
  * `max_dac [9:0]` — максимально допустимый код для ЦАП.

#### Математика инкремента с фиксированной точкой:
Параметры наклона `slope_1` и `slope_2` передаются в формате с фиксированной точкой: вещественное число (float), умноженное на масштабный коэффициент $2^P$ (где $P$ — статический целочисленный параметр модуля, задаваемый при компиляции) и приведенное к типу `uint32_t`. 

Приращение текущего значения усиления на каждом такте рассчитывается путем добавления значения `slope` к внутреннему 64-битному аккумулятору с последующим отсечением дробной части (младших $P$ бит):

$$Value_{next} = Value_{current} + \frac{Slope}{2^P}$$

#### Алгоритм генерации профиля:
1. По фронту синхроимпульса `i_dac_sync` (синхронизированного с запуском АЦП) выходы немедленно инициализируются значением `init_gain`.
2. В течение времени `delay_start` значение удерживается неизменным.
3. По окончании задержки начинается первая фаза роста: код плавно увеличивается на шаг `slope_1` каждый такт на протяжении `time_1` тактов.
4. По завершении первой фазы начинается вторая фаза роста: код увеличивается на шаг `slope_2` на протяжении `time_2` тактов.
5. На всех этапах формируемый код аппаратно ограничивается снизу значением `min_dac` и сверху значением `max_dac`.

#### Режимы совместной работы двух ЦАП (`vrc_type`):
* **Последовательный режим (Sequential, `vrc_type = 2'b01`):** Напряжение регулировки сначала подается на ЦАП 1. ЦАП 2 при этом жестко удерживается в состоянии `min_dac`. Как только выходной код для ЦАП 1 достигает максимального предела `max_dac`, его значение фиксируется, а код для ЦАП 2 начинает нарастать по заданному закону профиля от уровня `min_dac`.
* **Синхронный режим (Parallel, `vrc_type = 2'b10`):** Значения на оба ЦАП выдаются абсолютно одновременно и симметрично. Чтобы суммарное усиление двух последовательных каскадов AD604 соответствовало заданному профилю, текущее вычисленное значение кода делится на 2 (выполняется логический сдвиг вправо на 1 бит) перед выдачей в драйверы ЦАП.

## 5. Регистровая карта параметров

Распределение конфигурационных параметров в системе осуществляется на основе анализа адреса `i_cmd_addr[31:0]`. 
* Старший байт `[31:24]` задает доменный префикс (целевой аппаратный блок).
* Байт `[23:16]` указывает суб-адрес регистра внутри этого блока.
* Сами данные передаются по шине `i_cmd_data[31:0]`.

### 5.1. Накопитель A-скана `ascan_latch_param.v`
* **Префикс домена:** `i_cmd_addr[31:24] = 8'h02`  
* **Тактовая частота:** `adc_clk` (65 MHz)

| № | Суб-адрес `[23:16]` | Выходной порт | Диапазон `i_cmd_data` | Назначение параметра |
| :---: | :---: | :--- | :---: | :--- |
| **1** | `8'h01` | `o_n_samples` | `[15:0]` | Количество собираемых АЦП 12-битных отсчетов (слов) для `ascan` |
| **2** | `8'h02` | `o_accum` | `[7:0]` | Коэффициент накопления сигналов |
| **3** | `8'h03` | `o_accum_type` | `[3:0]` | Выбор алгоритма/типа накопления сигналов |
| **4** | `8'h04` | `o_delay_time` | `[15:0]` | Задержка старта захвата относительно импульса запуска `i_adc_sync` |

### 5.2. Логарифмический канал `log_latch_param.v` (настройка `src/log.v`)
* **Префикс домена:** `i_cmd_addr[31:24] = 8'h03`  
* **Тактовая частота:** `log_clk` (25 MHz)

| № | Суб-адрес `[23:16]` | Входной порт | Диапазон `i_cmd_data` | Назначение параметра |
| :---: | :---: | :--- | :---: | :--- |
| **5** | `8'h01` | `i_n_samples` | `[15:0]` | Суммарное количество отсчетов логарифмического канала для захвата |
| **6** | `8'h02` | `i_accum` | `[7:0]` | Коэффициент децимации/накопления логарифмического канала |
| **7** | `8'h03` | `i_accum_type` | `[3:0]` | Режим накопления данных (1 = Пиковый детектор, 2 = Интегратор) |

| **9** | `8'h05` | `i_skip_ticks` | `[15:0]` | Задержка старта захвата (пропуск тактов) в периодах частоты `log_clk` |

### 5.3. Высоковольтный импульс `pulse_latch_param.v`
* **Префикс домена:** `i_cmd_addr[31:24] = 8'h05`
