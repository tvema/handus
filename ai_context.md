# Global AI Project Configuration

это основные правиля для проекта.

частоты приходящие от PLL:
- sys_clk: 80MHz
- adc_clk: 65MHz
- log_clk: 25MHz
- dac_clk: 50Mhz
- hi_clk: 250MHz

для PLL есть свой .sdc файл в котором описаны все эти частоты

все ресеты и синки генеряться через модуль sync_cc для всех частот проекта

модуль sync_cc используется для кросклокинга сигнала i_sync приходящего на частоте sys_clk на все остальные частоты и для буферизации асинхронного сброса по всем частотам проекта
заголовок sync_cc выглядит вот так:
module sync_cc (
    // Входной тактовый сигнал домена sys_clk (80MHz) и глобальный сброс
    input  wire clk,         // sys_clk (80MHz) согласно правилу наименования
    input  wire rst_n,       // Асинхронный сброс (активный низкий)

    // Входной сигнал синхронизации в домене sys_clk
    input  wire i_sync,      // Сигнал внешней синхронизации

    // Тактовые частоты других доменов
    input  wire i_adc_clk,   // adc_clk: 65MHz
    input  wire i_log_clk,   // log_clk: 25MHz
    input  wire i_dac_clk,   // dac_clk: 50MHz
    input  wire i_hi_clk,    // hi_clk:  250MHz

    // Выходные синхронизированные импульсы для каждого домена
    output wire o_sys_sync,  // Синхронизирован в sys_clk (80MHz)
    output wire o_adc_sync,  // Синхронизирован в adc_clk (65MHz)
    output wire o_log_sync,  // Синхронизирован в log_clk (25MHz)
    output wire o_dac_sync,  // ... в dac_clk (30MHz)
    output wire o_hi_sync,   // ... в hi_clk (250MHz)

    // Выходные синхронизированные сбросы (активный низкий) для каждого домена
    output wire o_sys_rst_n, // Сброс для домена sys_clk (80MHz)
    output wire o_adc_rst_n, // Сброс для домена adc_clk (65MHz)
    output wire o_log_rst_n, // Сброс для домена log_clk (25MHz)
    output wire o_dac_rst_n, // Сброс для домена dac_clk (50MHz)
    output wire o_hi_rst_n   // Сброс для домена hi_clk  (250MHz)
);

входящие сигналы в модуле надо называть начиная "i_"
выходные сигналы в модуле надо называть начиная "o_"

сигнал сброса буферизируется в модуле sync_cc по каждой частоте, его надо называть "*_rst_n", * - с привзякой к частотному домену и без "i_" 
входящий сигнал входной тактовой частоты для модуля надо называть "*_clk" без буквы "i_" (sys_clk, adc_clk, log_clk, dac_clk, hi_clk)
входящий сигнал внешней синхронизации для запуска надо называть "i_*_sync" с привзякой к частотному домену

Описание основных модулей системы:

модуль param получает параметры на частоте sys_clk в виде двух 32 битных слов, 1-ое слово адрес команды, 2-ое слово данные команды, в зависимости от адреса команды, команда может обрабатываться на той же частоте или передаваться в другие модули, которые работают на других частотах, т.е. нужно в зависимости от старшего байта в адресе декодировать команду или передать её в соответствующий модуль для декодирования но на другой частоте, 1- sys_clk, 2 - adc_clk, 3 -log_clk, 4 - dac_clk, 5 - hi_clk, ! нужно считать, что все модули готовы к обработке команд всегда, а команда выдаётся с валидированием

модуль adc_latch_param для декодирования команд из модуля param на частоте adc_clk и защёлкивания параметров в регистры по сигналу i_adc_sync по частоте adc_clk для использования в других модулях на этой частоте в качестве параметров. декодируется адрес команды и в зависимости от адреса команды в соответствующий регистр запоминается аргументкоманды (данные команды), которые потом используются при следующем цикле запуска по i_sync. При значении адреса i_cmd_addr[23:16] == 1 в i_cmd_data[15:0] приходит параметр количество накапливаемых слов для модуля ascan

модуль pulse для реализации работы 
В модуле pulse нужно организовать автомат, который будет запускаться из состояние "none" по сигналу i_hi_sync и переходить в состояние "charge power" и находится в этом состоянии i_charge_time тактов, потом переходить в состояние "transmit power" и находится в этом состоянии i_transmit_time тиков, потом переходить в состояние "strike" и находится в нём i_pulse_width тактов, после чего переходить в состояние "power off" и находится в нём минимум 200 тактов и дальше ждать следующего старта i_hi_sync
состояние выходов в зависимости от состояния автомата:
none - porer_on=off strike=0ff
charge - power_on=on strike=on
transmit - power_on=on strike=off
strike - power_on=on strike=off
power off - power_on=off strike=off

модуль ascan работает на двух частотах, входной поток поступает на частоте adc_clk на вход i_in_data и представляет из себя поток 12 битных данных, которые приходят каждый такт этой частоты, после сигнала i_sync (на частоте adc_clk) начинается приём этих данных, упаковка в 32-х битные слова и запись в двухпортовую память (сли есть дефайн TESTMODE, то используется програмная реализация "заглушка", иначе двухпортовая память Quartus altsyncram), после накопления в памяти N отсчётов, на выход модуля выдаётся сигнал готовности o_data_ready, на частоте sys_clk и на выход o_out_data модуля начинают выдаваться в упакованном виде словами по 32 бита, на частоте sys_clk данные, которые квитируются сигналами o_out_vld и выдаются по готовности приёмника i_out_rdy, память модуля представляет из себя два буффера "бабочка", которые перещёлкиваются и пока выдаётся данные из одного буфера, запись данных производится в другой

модуль vrc работает на частоте dac_clk, он служит для выдачи значений в 2 ЦАПа, которые управляют усилителями (включенными последовательно AD604) с управлением усилением напряжением, модуль принимает входные параметры "тип vrc [1:0]", "время задержки начала [15:0]", "начальное усиление [10:0]", "скорость нарастания 1 [31:0]", "время наростания 1 [15:0]", "скорость наростания 2 [31:0]", "время нарастания 2 [15:0]", "минимальное значение DAC [9:0]", "максимальное значение DAC [9:0]", лгика работы такая: после i_adc_sync нужно выставить начальное усиление, после задержки усиление начинает инкрементироваться на "скорость нарастания 1" в течении времени "время наростания" после чего значение начинает увиличиваться на "скорость наростания 2" в течении "времени нарастания 2", выходные данные это два значения [9:0] для двух ЦАПов DAC101S101, каждый ЦАП должен регулироваться от минимального до максимального значения (которые указаны во входных парах), регулировка усиления должна быть 2-х типов, первый - это когда регулеровка происходит последовательно (т.е. 2-ой ЦАП включается на минимальное значение и начинает регулироваться (нарастать) только после того как значение на 1-ом ЦАПе достигли максимума) и второй вариант - это когда значения выдаются на оба ЦАПа одинаковые (в этом режиме надо учесть, что значение надо поделиться на 2 чтобы суммарное усиление не изменилось), значение в параметрах наростания представляют из себя значения float умноженные на 2^P и засунутые в uint_32 (P - задаётся как параметр для модуля)
